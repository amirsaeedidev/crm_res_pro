# پنل مدیریت CRM رستوران — نسخه متصل به Supabase

این پروژه Flutter برای Android و Flutter Web طراحی شده و دادهٔ مدیریتی آزمایشی تولید نمی‌کند. منبع اصلی داده‌ها Supabase مشترک با اپ رستوران است. این تحویل خطاهای کامپایل شناخته‌شده در گزارش کاربر را اصلاح کرده، اتصال Realtime و چند بخش مدیریتی جدید را اضافه کرده و schema راه‌دور Supabase را نیز به‌روزرسانی می‌کند.

## اتصال و اجرا

آدرس پروژه در `lib/core/config/supabase_config.dart` روی آدرس تأییدشده قفل شده است تا اشتباه تایپی در Flutter Web باعث `Failed to fetch` نشود. فقط Publishable Key هنگام اجرا/Build تزریق می‌شود؛ فایل `.env` با کلیدهای اتصال داخل بسته یا خروجی وب قرار نمی‌گیرد. **هرگز `service_role` یا Secret Key را در اپ Flutter یا وب قرار ندهید.** Publishable/anon key برای کلاینت است و امنیت داده با RLS و بررسی نقش مدیر اعمال می‌شود.

PowerShell (مقدار کلید را از Supabase Dashboard بگیرید؛ آن را داخل سورس کد ننویسید):

```powershell
flutter pub get
flutter run `
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_SB_PUBLISHABLE_KEY
```

Build اندروید:

```powershell
flutter build apk --release `
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_SB_PUBLISHABLE_KEY
```

Build وب:

```powershell
flutter build web --release `
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_SB_PUBLISHABLE_KEY
```

در صورت نیاز نام باکت تصویر را هم اضافه کنید: `--dart-define=SUPABASE_STORAGE_BUCKET=products` و `--dart-define=SUPABASE_CATEGORY_ICONS_BUCKET=categories`.

> آدرس ثابت پروژه: `https://cfdzxtnkiptnlitwvnla.supabase.co`. اگر عمداً به پروژه دیگری منتقل شدید، مقدار `url` در فایل تنظیمات را تغییر دهید و وب را دوباره Build کنید.

## قابلیت‌های موجود

- مدیریت مشتری، سفارش، میز و رزرو، دسته‌بندی، محصول، بنر، تخفیف، تیکت، گزارش، فایل و باشگاه امتیازی؛ فهرست‌ها به Supabase متصل‌اند.
- کد تخفیف عمومی یا اختصاصی برای مشتریان انتخاب‌شده با جستجوی نام/شماره، سقف مصرف کلی و سقف جداگانه برای هر مشتری؛ تاریخ پایان تا انتهای روز انتخاب‌شده معتبر است. اعتبار کد و شمارنده مصرف در RPC ثبت سفارش سمت Supabase دوباره کنترل می‌شود.
- مدیریت **کیف پول پولی مستقل از امتیاز وفاداری**: شارژ، کاهش موجودی با ذکر دلیل، نمایش تاریخچه و ثبت هر تغییر در دفتر گردش مالی.
- مدیریت انبار: ثبت ماده اولیه و واحد، هزینهٔ واحد، حد هشدار، ورود/خرید و میانگین بهای تمام‌شده، اصلاح موجودی، ثبت ضایعات/مرجوعی، گردش انبار و هشدار کمبود.
- دستور مصرف برای هر غذا: انتخاب محصول و ماده اولیه، ثبت مقدار به ازای هر غذا، نمایش توضیح موجودی/بهای واحد با Tooltip و محاسبهٔ هزینهٔ مصرف. زمان انتقال سفارش به «در حال آماده‌سازی»، میزان مواد از انبار به‌صورت اتمیک کم می‌شود؛ اگر مواد کافی نباشد تغییر وضعیت متوقف می‌شود. برای جلوگیری از کسر دوباره در تغییر رفت‌وبرگشتی وضعیت، مصرف سفارش idempotent است.
- نوتیفیکیشن مدیریتی ذخیره‌شونده برای سفارش، رزرو، مشتری و تیکت جدید، با همگام‌سازی Realtime.
- فاکتور و رسید آشپزخانه PDF برای هر سفارش: نام فروشگاه و لوگو، تاریخ/ساعت، شناسه و نوبت روز، نوع سفارش، میز، اقلام و تعداد، قیمت، جمع، تخفیف/کد تخفیف و مبلغ نهایی. چاپ A4 یا رول ۵۸/۸۰ میلی‌متری و اشتراک فایل PDF در Android/Web.
- تنظیمات فاکتور از داخل تنظیمات پنل: نام فروشگاه، URL لوگو، تلفن/آدرس، متن سربرگ/پاورقی، اندازهٔ کاغذ و نمایش/مخفی کردن بخش‌های مختلف.
- آپلود تصویر با bytes به‌جای `dart:io File` برای سازگاری Web/Android، محدودیت حجم و اعتبارسنجی فرمت.
- اصلاح اتصال Supabase برای استفاده از `publishableKey`، بهبود مسیرهای Realtime و ثبت خطا، و حذف `.env` واقعی از بسته.

## وضعیت Supabase

روی پروژهٔ متصل، migrationهای زیر اعمال شده‌اند (همراه با migrationهای پیشین پروژه):

- `crm_wallet_inventory_receipt_notifications` — کیف پول پولی، گردش انبار، دستور مصرف، تنظیمات رسید، اعلان‌ها و نوبت روز.
- `crm_receipt_queue_view_update` — افزودن جمع، تخفیف، شماره میز و نوبت روز به `orders_view` با `security_invoker`.
- `crm_inventory_consumption_idempotency_and_local_queue` — شمارهٔ نوبت روز بر اساس `Asia/Baku` و جلوگیری از کسر دوباره مواد اولیه.
- `crm_wallet_inventory_fk_indexes` — ایندکس‌های کلید خارجی برای تاریخچه‌های جدید.
- `crm_customer_wallet_currency_toman` — تنظیم واحد نمایشی کیف پول روی تومان (`IRT`).
- `crm_wallet_ledger_security_inventory_movements` — محدودکردن تغییر مستقیم دفاتر مالی و افزودن ثبت ضایعات/مرجوعی.

نسخه‌های SQL قابل تکرار تغییرات جدید در `supabase/manual/008` تا `019` قرار دارند. این فایل‌ها برای ثبت تاریخچه یا نصب در محیط دیگر نگه داشته شده‌اند؛ روی پروژهٔ اصلی این تغییرات قبلاً اعمال شده‌اند. migrationهای 014 تا 017 سیاست خواندن کیف پول، Realtime، مجوز ستون موجودی و بهینه‌سازی نوبت روز/واحد پول را تکمیل می‌کنند.

## امنیت

- در Supabase تابع توسعه‌ای `dev-phone-login` به نسخهٔ غیرفعال ارتقا یافت؛ کد ثابت `1234` دیگر مسیر ورود ندارد و Function اکنون `verify_jwt=true` دارد. ورود عادی برنامه از مسیر احراز هویت موجود انجام می‌شود.
- نوشتن موجودی کیف پول و دفاتر مالی از طریق RPCهای سمت دیتابیس، با کنترل `public.is_admin()` و تراکنش اتمیک انجام می‌شود. دفاتر تراکنش برای نقش authenticated فقط خواندنی هستند؛ مشتری عادی تنها ردیف/تراکنش خودش را می‌تواند بخواند.
- جدول‌های جدید RLS فعال دارند. برای استفادهٔ مشتری از کیف پول، خواندن به مالک همان کیف پول محدود است.
- کلید واقعی ملی پیامک در Vault باقی می‌ماند، نه سورس Flutter. پیامک در تنظیمات خاموش است تا پیکربندی واقعی اپراتور انجام شود.
- Supabase Security Advisor پس از تغییرات هنوز هشدار `pg_net` در schema `public` را گزارش می‌کند و محافظت رمزهای لو رفته غیرفعال است. هشدار تعدادی از `SECURITY DEFINER`ها نیز باقی است؛ توابع مدیریتی افزوده‌شده کنترل نقش در بدنه دارند، اما قبل از انتشار باید تنظیم Password Security در Dashboard فعال و هشدارها دوباره بررسی شوند. به دلیل وابستگی زمان‌بند پیامک، جابه‌جایی `pg_net` خودکار انجام نشده است.

## بررسی و تست

در محیط آماده‌سازی Flutter/Dart SDK نصب نبود؛ بنابراین `flutter analyze`, `flutter test`, `flutter build apk` و `flutter build web` در این محیط اجرا نشده‌اند. خطاهای شناخته‌شدهٔ کامپایل از گزارش اولیه در سورس اصلاح شده‌اند، اما پیش از انتشار باید در سیستم دارای Flutter با فرمان‌های زیر بررسی شوند:

```powershell
flutter pub get
flutter analyze
flutter test
```

بعد از آن هر دو خروجی Android و Web را جداگانه build و آزمایش کنید، مخصوصاً چاپ PDF، انتخاب فایل، realtime، تراکنش کیف پول و جلوگیری از تغییر سفارش با موجودی ناکافی.
